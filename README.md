## Capstone Project

### BloodBridge: Emergency Blood Donor Matching Application

BloodBridge is a cloud-based emergency blood donor matching application designed to connect patients and people in need of blood with suitable blood donors during emergency situations.

The application aims to make the blood donor matching process faster and more efficient by maintaining donor information, processing emergency blood requests, matching compatible blood groups, and sending alerts to suitable donors.

Cloud computing provides the infrastructure required to store donor and request information, process blood-matching operations, support multiple users, and scale the application according to demand.

## Cloud Computing in BloodBridge

Cloud computing plays an important role in the BloodBridge application by providing scalable and accessible computing resources.

The cloud backend can store donor profiles, blood group information, emergency blood requests, and matching results. When the number of users or emergency requests increases, cloud scalability and elasticity can help the application handle the additional workload.

Web services and REST APIs can enable communication between the BloodBridge user interface and the cloud backend. Cloud-based storage and databases can provide centralized access to required information.

## Service Model Application

### IaaS
IaaS can provide the virtual computing infrastructure, networking, and storage required to host the BloodBridge application.

### PaaS
PaaS can provide a managed environment for developing, deploying, and running the BloodBridge backend and APIs.

### SaaS
The BloodBridge application can be delivered to users as an online software service accessible through a web or mobile interface.

### XaaS / Specialized Services
Specialized cloud services can support authentication, notifications, monitoring, analytics, and other application requirements.

## Capstone Cloud Flow

A typical BloodBridge cloud workflow is:

**User → BloodBridge Application → REST API → Cloud Backend → Cloud Database → Blood Matching Process → Alert / Response**

For example, when a user submits an emergency blood request, the request is sent through the application to the cloud backend using an API. The backend processes the request, searches the cloud database for compatible donors, and returns the matching results or sends emergency notifications.
